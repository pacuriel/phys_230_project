## Biological Background

We had presented on modeling the process of contact inhibition of locomotion (CIL). Mesenchymal-to-Epithelial Transition (MET), another collective cell behavior process, made more sense to me (Pablo), so I focused on this process. A high-level overview of this process is described below. 

#### Mesenchymal-to-Epithelial Transition (MET)

MET is an important biological process where cells transition from migrating semi-freely amongst each other (mesenchymal) to a more collectively aligned migration where cells are affected by the trajectory of neighboring cells (epithelial). After enough collective migration and cell replication, cells can clump up to form "sheets" of cells. This process plays an important role in human development and cancer metastasis. 

## Simulating MET (Aim 1)

Our first aim was to develop an agent-based (random walk) model to simulate collective cell behavior during MET. This is completed in the file `rw_model.py`. Initially, the model was the exact same as the random walk model from our Lab 2 notebook. I incrementally updated this file to include MET-like aspects (e.g. random $\to$ directed motion). Currently, the simulation does not form sheets, but I believe this is because I omitted implementing cell replication. 

The goal was to make this file object-oriented and modular to allow for easier customizibility and reproducibility. While I don't think it is terrible, I do acknowledge that some OOP principles went out the window as the due date quickly approached. 

### SimMet Class

In short, this is where the *magic* happens. I will discuss the file in detail in this section. First, we begin by setting relevant simulation parameters in the functions `__init__`, `set_sim_vars`, `get_sim_name`, and `setup_plotting`. The simulation takes place in the `simulate` function (Would you have guessed?). At each time step, we use `update_met_state` to toggle and strengthen MET-like dynamics. 

The MET-like dynamics are added through the use of an "interaction radius". In `get_new_angles`, we check to see if any cells are within a given cell's interaction radius. If so, then that cell's direction is updated to be the average of all of the cells in the interaction radius. This is done for all cells in the simulation at each time step. If no cells are present in the radius, then we use the same update formula from Lab 2. Also, we use a `noise` variable to add further noise to the cell movements. As the MET process progresses, `update_met_state` reduces the noise and increases the interaction radius. This results in MET-like behavior where the cells move almost in sync. `apply_bounds` is used to keep the cells enclosed in a region (e.g. petri dish in a lab) throughout the duration of the simulation. 

`extract_global_features` was generated by a LLM (you know the one) and never used. The idea was that this function could be used to generate more descriptive (for the model, that is) features instead of just raw trajectory data. I talk about this more in the "Future Directions" section below. 

## Predicting Model Parameters with ML (Aim 2)

This aim was focused on trying to use machine learning (ML) to infer key parameters from simulation data. A basic multi-layer perceptron (MLP) was used for this task. The parameters of interest included: the time the MET process was toggled on, the time the MET process was strengthed fully, the three random noise levels used at each stage, and the first and last interaction radii. Note: the second radius wasn't used because it is frequently updated during the initial MET stage. Therefore, we are trying to predict a vector $\hat{y} \in \mathbb{R}^7$. The dataset, MLP, and training process are described below. 

### Simulated Dataset

We ran 10,000 simulations to form our dataset. Due to MLP's fixed input size, all simulations had $N=40$ cells and $T = 100$ time steps, which is biologically consistent with the data provided by Dr. Woo's lab. The seven parameters to be predicted were varied for all simulations. For simplicity, we chose to use the raw trajectory data as input (bad choice). Each simulation results in a trajectory tensor of form $X \in \mathbb{R}^{N \times T \times 2}$. The MLP flattens this into a vector of size $2NT$ (= 8,000 for our case) for its input. The data was generated using the `gen_sim_data.py` file. 

### MLP Structure

A subgoal of this aim was to keep the model relatively simple. The model consists of: an input layer, two hidden layers, and an output layer. The ReLU activation function is used in each hidden layer. I experimented using Dropout in hopes of reduce overfitting, but it did not have much effect. I played with the size of the hidden layers, but it also did not do much.

### Training Process

I trained the model for $\approx 10-30$ epochs (full passes through the training data) each time. The train/test splits were $\approx 75/25$. The loss function used was a standard mean squared error (MSE). The weights of the model were updated using the commonly used ADAM optimizer. 

### How did it do? 

Not great. Some may even say terrible. I only ran a handful of experiments messing with the model, but I did not notice any improvements. A few train/test loss curves are shown in `mlp/experiments`. The model badly overfits in every experiment. I believe this makes sense given the nature of the training data. The raw trajectory data and all of its noise is too much for the model to handle in its current form. The test loss repeatedly plateaus around $40$. 

#### Possible Improvements

I believe this problem could benefit from a more sophisticated model, better engineered features, and more data. A model like CNNs or LSTMs may be better suited to handle this data. Also, I think the model having an input vector of size 8,000 and immediately downsampling to $\approx 64-256$ may be discarding relevant information. `extract_global_features` was developed with the goal of using it to obtain better input features for the model instead of raw trajectory data. The model would likely have benefitted from further pursuit of this idea. Lastly, more data ($N \gg 50,000$ samples) would likely boost the model's ability to learn such complex dynamics.
